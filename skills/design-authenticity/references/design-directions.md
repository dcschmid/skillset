# Design Directions — inspiration, not templates

Purpose: give CREATE a vocabulary so output is NOT a new single house style. Each
direction = a set of principles to instantiate PER product. Never paste a
direction wholesale; derive project-specific type/color/layout from it. The point
is variety with rationale, not a bigger menu of templates.

## How to use

1. From product/audience/task (Discovery) shortlist 1–3 plausible directions;
   discard ones that fight the task (dense data ≠ maximal decoration).
2. For the chosen direction, write 3 concrete, checkable decisions (e.g.,
   "editorial: 2-family serif/sans pair, 1.35 scale, asymmetric hero grid").
3. Validate against the quality gate; a direction never overrides a11y or
   product-fit. Multiple viable → compare briefly, pick, say why.

## The set (principles to derive from)

- **Editorial** — typographic hierarchy, varied section rhythm, generous measure,
  asymmetric grids, imagery as article. For: magazines, docs with voice, portfolios.
- **Minimalist** — few elements, precision spacing, restraint carries quality. For:
  tools where calm = competence. Avoid = empty/boring; requires exact spacing.
- **Brutalist** — raw structure, visible borders, system type, high contrast,
  functional ornament. For: dev-tools, design-forward sites. Keep operable.
- **Swiss / International** — strict grid, sans type, objective hierarchy,
  whitespace as order. For: corporate/informational needing clarity.
- **Retro** — era-faithful type/palette/grain (70s, 80s, Y2K). For: cultural,
  music, playful brands. Consistency to one era, not costume.
- **Industrial** — utilitarian, labels/metadata, mono/technical type, restrained
  color, function visible. For: ops tools, dashboards, hardware.
- **Futurist** — spatial depth, neon-on-dark, geometric precision (NOT default
  purple-blue). For: tech/AI products wanting edge. Effects carry meaning.
- **Corporate** — conservative type, brand-anchored neutrals, predictable rhythm.
  For: enterprise where trust = low friction. Not = template SaaS.
- **Playful** — rounded, expressive type, motion, brighter palette. For consumer/
  education/games. Keep information architecture serious.
- **Typographic** — type IS the layout; scale/weight/measure are the design. For
  editorial/creative where words lead. Contrast-driven.
- **Information-dense** — high data-per-screen, tabular, tight leading, minimal
  chrome. For dashboards/admin/analytics. Scannable > pretty.
- **Premium** — restrained palette, refined type spacing, high-quality media,
  generous negative space. For luxury/fintech. Restraint ≠ empty.
- **Experimental** — unexpected grids/overlap/motion in service of content. For
  creative portfolios, campaign sites. Must stay navigable.
- **Gaming** — themed HUD/menu language, diegetic UI, engine-font constraints,
  strong state legibility. For games/launchers. Not = SaaS dashboard dressed up.
- **Pixel-inspired** — grid-snapped, bitmap/low-res type, chunky borders. For
  retro games/dev-toys. Discipline to the pixel grid.
- **Musical** — rhythm/tempo in layout, expressive display type, mood palette.
  For music media/artist/Bandcamp-like.
- **Technical** — mono/code-forward, spec-sheet layout, precise micro-labels. For
  SDKs, API docs, engineering tools.
- **Organic** — soft geometry, natural palette, hand/crafted touches, asymmetric
  flow. For wellness, culture, eco. Still needs structure.

## Rules

- One project ≠ one direction forever: a project MAY mix (e.g., industrial +
  typographic), but the mix is stated and coherent.
- Never impose these onto an existing system that already works (Design System
  Preservation); they seed NEW or explicitly-redesigned surfaces.
- Directions do NOT license slop: "Futurist" ≠ glow blobs; "Playful" ≠ random
  circles. Effects stay justified (`anti-ai-patterns.md`).
- Output must be product-recognizable after a name-swap test (`anti-ai-patterns.md` E).
